# Proposal-to-NXT command audit

**Source:** `Pokemon_MMO_Complete_Server_Command_Proposal(2).docx`, supplied by Akuma. This document preserves all 148 command rows in their original order, including aliases and overloaded syntax. The original proposed rank is retained as proposal metadata only: NXT does **not** grant console authority to any game account, VIP or staff rank. Every installed command runs exclusively through the OS-controlled interactive world-server terminal.

**Selection:** adapt commands whose underlying mechanics already exist; exclude all communication commands by request; explicitly defer unsupported frameworks rather than implementing empty or misleading handlers. “Adapted” does not mean the proposal's exact original behavior was copied: the final column and the main manual describe intentional safety/scope changes.

The implemented catalog has **81 canonical commands and 21 aliases**; ten are developer-gated and thirty require confirmation. Additions such as `setvariety`, catalog search, `confirm`, `cancel`, `cancelshutdown`, `collection` and safe `testbattle` support NXT's existing systems and the local-console workflow. Normal commands are still administrative, never player-facing chat commands.

## Proposal requirements retained and adapted

Local OS possession replaces the proposed in-game rank ladder. Dynamic help respects per-command disabling and the developer gate. Successful administrative operations have a transactional account-targeted database audit; local rotating logs also record requests, previews and rejections. Destructive commands require single-use, expiring, state/session-bound confirmation. Exact names and IDs are supported. Syntax errors are explicit. No command prints password hashes, DB credentials, private certificates or another account's credentials to game clients. Generated reset/test-account passwords appear only after commit in the local terminal and are excluded from audits. Complete command details and configuration are in `LOCAL_ADMIN_CONSOLE.md`.
